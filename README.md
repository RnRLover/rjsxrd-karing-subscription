# rjsxrd: Karing direct + RU direct + автоматический прокси

## Подписки

- INCY: https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/ru-karing-incy.txt
- Happ: https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/ru-karing-happ.txt

В каждой ссылке два полных Xray-профиля: «Для обычного интернета» (источник igareck BLACK_VLESS_RUS.txt) и «Для белых списков (если не работает)» (rjsxrd bypass-all.txt). Режим выбирается вручную; внутри каждого до 24 проверенных узлов разных поддерживаемых протоколов и один автоматический балансировщик. Автоматическое распознавание белых списков отсутствует.

## Маршрутизация после изменения 2026-10-04

Из рекомендованного российского профиля Karing используются **группы с действием direct и рекламные фильтры Adblock/AdblockPlus**, в исходном порядке. Сейчас это OneDrive и Apple (основные домены, разработчики, сертификаты, обновления).

Порядок маршрутов в обоих режимах:

1. Служебная обработка DNS/FakeDNS.
2. Частные и локальные IP → напрямую.
3. Adblock и AdblockPlus из Karing → блокировать; затем OneDrive и Apple → напрямую.
4. Наши российские домены (category-ru) → напрямую.
5. Наши российские IP (geoip:ru) → напрямую.
6. Всё оставшееся TCP/UDP → автоматический прокси.

Первое совпавшее правило определяет маршрут. Отдельных прокси-групп Google, Gemini, Microsoft, игр и других сервисов больше нет. **Anticensor удалён.** Группы malware, phishing и cryptominers не импортируются; Adblock и AdblockPlus сохранены. Дополнения category-ads-all, google-gemini и явные Google API-домены также удалены. Блокировка рекламы использует исходные списки Adblock и AdblockPlus без наших дополнений.

Правила фильтруются по действию при каждой сборке: последующие обновления Karing не возвращают удалённые группы. Прямые группы и два рекламных фильтра загружаются и преобразуются в пользовательские геофайлы. Стандартные категории Xray сохраняются в базах, но их наличие само по себе не включает маршруты.

Отдельные ru.json и normal.json содержат лишь локальные/RU прямые исключения и последний общий прокси-маршрут. ru-karing.json — отдельный полный whitelist-конфиг с прямыми группами Karing. При недоступности всего пула fallbackTag=block блокирует прокси-трафик; это защита от прямого выхода, а не рекламный фильтр.

## DNS и FakeDNS

FakeDNS использует 198.18.0.0/15, кэш 4096 имён и восстановление домена при соединении. Для реальных адресов прямых доменов используется Яндекс 77.88.8.8 / 77.88.8.1. Для остальных имён и общего резерва — 1.1.1.1. Домены, классифицируемые только по GeoIP после разрешения, используют общий DNS. DNS-запросы проходят служебный прямой маршрут dns-bootstrap. Для перехвата DNS устройства нужен VPN/TUN; системный HTTP-прокси этого не обеспечивает.

## Форматы клиентов

INCY получает компактный массив полных конфигов и строку ://autorouting/onadd/ с karing-routing.json. Этот профиль устанавливает и обновляет karing-geosite.dat и karing-geoip.dat. Бюджет каждого full-конфига — 250 КБ UTF-16 из-за ранее наблюдавшегося Android TransactionTooLargeException. Изменение полного конфига требует обновления подписки и переподключения; геофайлы обновляются через autorouting клиента. Совместимость зависит от версии INCY и требует проверки реального импорта.

Happ получает чистый JSON-массив без дополнительных строк: все используемые домены и подсети встроены, внешние геофайлы не требуются. Интервал обновления задаётся в клиенте. Happ на компьютере пользователя не запускается в ходе разработки. Нативный импорт и VPN/TUN не подтверждаются проверкой Xray; расход памяти не измерен.

## Источники и обновление

GitHub Actions получает свежие источники, выполняет тесты, проверяет реальные HTTPS-выходы через Xray, собирает маршруты и публикует файлы одним коммитом после проверки. Расписание — каждый час; GitHub может задерживать запуск. Ошибка одного из обязательных этапов сохраняет предыдущую опубликованную подписку.

Публичный российский входной IP и RU-метка допускаются лишь при проверенном зарубежном HTTPS-выходе. Российский, локальный, неизвестный или недоступный выход не публикуется. servers.txt и normal-servers.txt содержат только выбранные проверенные узлы.

burstObservatory + leastPing оценивают доступность и задержку HTTP-проб с устройства. Генератор не выбирает сервер по пингу Actions. Проверка HTTPS не подтверждает пригодность для Gemini, конкретной игры или UDP. Смена выхода может разорвать игровую сессию; для UDP нужен подходящий туннель клиента.

check_ru.py дополнительно проверяет TCP-порты выбранных адресов через до трёх живых RU-точек Check-Host. Отчёты: ru-reachability.json и normal-reachability.json. Передаются только публичные адреса/порты без UUID и паролей. Статусы reachable/unreachable/unknown не изменяют пул; API-сбои не блокируют публикацию. TCP-успех не доказывает работу VPN, UDP или обход белых списков мобильного оператора.

## Локальная сборка

Python 3.12+, стандартная библиотека. Xray 26.3.27 и sing-box 1.14.2 скачиваются официальными setup-скриптами с проверкой контрольных сумм.

```text
python -m unittest discover -v
python setup_xray.py
python setup_singbox.py
python generate.py --xray .runtime/xray --verify-exits
python generate.py --xray .runtime/xray --verify-exits --pool normal
python check_ru.py
python karing.py --xray .runtime/xray --singbox .runtime/sing-box
python check_fakedns.py --xray .runtime/xray
python check_fakedns.py --xray .runtime/xray --config ru-karing-happ.txt --profile-index 0
python check_fakedns.py --xray .runtime/xray --config ru-karing-happ.txt --profile-index 1
```

Windows использует .runtime/xray.exe и .runtime/sing-box.exe. rjsxrd_parser.py переиспользует MIT-конвертер rjsxrd (source/utils/vpn_config.py, commit 3c6df4dee94c434c19c6e1dfaed3c3f37fc5573d); лицензия сохранена в LICENSE.rjsxrd.
