# Подписка rjsxrd для INCY

Добавьте в актуальный INCY один URL:

https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/subscription.json

Подписка содержит компактный общий автовыбор и профили стран, объединяющие все пригодные технологии каждой страны. Страны и состав их пулов определяются из свежего rjsxrd при каждой сборке. Новые группы появляются автоматически, исчезнувшие удаляются из следующей публикации. Список стран или технологий вручную не задаётся.

Каждый полный Xray-конфиг повторяет клиентскую логику предоставленного образца: IPv4, `leastLoad`, геоблокировка рекламы и телеметрии Windows, его прямые маршруты и исключения. DNS полностью совпадает с образцом: Яндекс DoH, Cloudflare DoH и обычный Cloudflare DNS в резерве. Серверы, авторизация, порты, ключи, SNI, пути и обязательные параметры транспортов берутся из rjsxrd. Данные доступа из образца в репозитории отсутствуют.

Доставка — один JSON-массив на первой строке и метаданные названия подписки. Отдельного профиля маршрутизации и команд Routing/Autorouting нет. Прежний отдельный профиль следует оставить выключенным. Геобазы нужны Xray и используются из файлов INCY; CI проверяет конфиг со свежими файлами Loyalsoldier, но не подтверждает состояние геофайлов на телефоне.

## DNS

Порядок серверов сохранён относительно образца:

| Позиция | Сервер | Назначение |
|---|---|---|
| 1 | `https://77.88.8.8/dns-query` | Яндекс DoH, категории `category-ru` и `category-gov-ru` имеют приоритет |
| 2 | `https://1.1.1.1/dns-query` | Cloudflare DoH |
| 3 | `1.0.0.1` | Обычный Cloudflare DNS по UDP/53 |

Как в образце, у Яндекса не включён `skipFallback`: он может обслуживать также нероссийские имена. При отказе обоих DoH разрешён обычный UDP-резерв Cloudflare. Проверка сертификатов HTTPS сохранена. Блокировка рекламы выполняется геосписками маршрутизации, а не фильтрующим DNS.

В DNS нет добавленных нами `tag`, `hosts`, закреплённых адресов AdGuard и отдельного прямого правила. DNS-запросы подчиняются тем же правилам маршрутизации, что в образце: IP Яндекса совпадает с `geoip:ru` и идёт напрямую, IP Cloudflare обычно попадают в балансировщик. Поэтому работа резервного DNS может зависеть от пула; отдельного прямого bootstrap подписка не задаёт. INCY может дополнить правила своими DNS-IP-исключениями.

Режим VPN DNS задаёт INCY. Как в образце, JSON не содержит собственного перехвата клиентского TCP/UDP-порта 53 или отдельного DNS-outbound. Режим Internal (mapped) и работу системного TUN обеспечивает клиент. `UseIPv4` используется во встроенном DNS, прямом выходе и сокетах прокси; системный переключатель IPv6 подписка не изменяет. Наличие буквального IPv6-адреса не означает, что JSON блокирует IPv6 на уровне системы.

## Маршрутизация

Правила проверяются в следующем порядке:

| Назначение | Маршрут |
|---|---|
| GitHub: `geosite:github`, основные домены и CDN с поддоменами | Напрямую |
| `geosite:win-spy`, `geosite:category-ads` | Блокировать |
| BitTorrent | Напрямую |
| Habr, 4PDA, перечисленные в образце `.ru`/`.su`-исключения | Через пул |
| `private`, `apple`, `twitch`, `category-gov-ru`, `category-ru` | Напрямую |
| `geoip:ru`, `geoip:private` | Напрямую |
| Остальной TCP/UDP | Общий балансировщик |

Список прокси-исключений: `habr.com`, `4pda.to`, `kemono.su`, `jut.su`, `kara.su`, `theins.ru`, `tvrain.ru`, `echo.msk.ru`, `the-village.ru`, `snob.ru`, `novayagazeta.ru`, `moscowtimes.ru`. Синтаксис доменов сохранён из образца.

GitHub направляется напрямую первым правилом во всех полных профилях. Используется категория `geosite:github` из Loyalsoldier; дополнительно явно указаны домены `github.com`, `githubusercontent.com`, `githubassets.com`, `github.io`, `github.dev`, `githubapp.com` и `ghcr.io` вместе с поддоменами. Это покрывает сайт, API, Raw, Pages, контейнерный реестр и скачивание релизов. Общие домены Amazon S3 и Azure целиком в прямой маршрут не добавляются. Правило действует и на доменное имя, полученное sniffing.

Используется `AsIs`: домены специально не разрешаются ради GeoIP. Дополнительных правил `.ru`/`.su`/`.рф` и блокировки нулевых DNS-адресов нет. SOCKS/HTTP-входы и отсутствие явного `listen` сохранены из образца, порты 10808/10809; sniffing включает HTTP и TLS без QUIC и без `routeOnly`.

## Автовыбор и транспорты

| Профиль | Состав | Автовыбор |
|---|---|---|
| `⚡ Автовыбор` | По одному лучшему представителю страны, до 64 узлов | `expected: 1`, веса 1/2 |
| Страна | Все пригодные протоколы и транспорты страны в одном профиле | `expected: 4`, `baselines: [400ms, 800ms]`, равные веса |

Внутри страны узлы сортируются по признакам кандидата для БС, доле успешных HTTPS-проверок, медиане времени ответа и разбросу задержки. При равенстве этих показателей сохраняется исходный порядок rjsxrd. Страны располагаются по тем же показателям своего первого, лучшего узла: страны с БС-кандидатами идут выше обычных. Алфавитная сортировка и отдельные профили технологий не используются.

Лимита в пять или пятьдесят серверов на страну нет. Страна получает один профиль, если весь её пул помещается в защитный бюджет полного конфига. Только при превышении 800 000 байт UTF-16 она разбивается на последовательные части; они стоят рядом и сохраняют ранжирование без потери узлов. Общий автовыбор собирается после всех стран и получает один лучший узел каждой страны, даже если её пришлось разделить. При заполнении лимита 64 сохраняется порядок приоритета стран.

В общем автовыборе допускаются максимум два узла с одним обнаруженным выходным IP и один узел на сочетание выходного IP и технологии. При неизвестном выходе используется адрес подключения; все неизвестные выходы не объединяются в один. Это ограничивает корреляцию отказов, но не доказывает независимость провайдеров. Совпадение входного CDN-IP само по себе не является основанием удалять разные подключения. Все остальные узлы остаются в профилях стран. Общий автовыбор не переключается автоматически на другой полный профиль.

Страна берётся из явного `OUT`/`EXIT`, единственного флага или повторённого кода страны в структурированной метке rjsxrd. Несколько разных флагов без явной метки выхода, противоречивые страны у дублей и отсутствие метки означают «Страна не указана»; такие узлы сохраняются. Флаги ЕС/ООН не считаются странами. Это группировка по метаданным источника, а не независимое подтверждение географии выхода; геолокация входного IP не подменяет выход.

Каждый профиль имеет собственные `outbounds`, балансировщик и наблюдатель. Неактивные полные профили не входят в список проверок активного Xray. Наблюдатель проверяет `https://www.gstatic.com/generate_204`; средний интервал 5 минут, два последних результата, тайм-аут 5 секунд, метод HEAD по умолчанию Xray. Это статистика недавних наблюдений в памяти клиента, а не сохранённая история GitHub. Выбор учитывает разброс задержки, отказы и веса, не измеряет пропускную способность или загрузку CPU сервера. Реакция на отказ зависит от расписания проверок. `expected: 4` с baselines не является жёстким лимитом числа выбранных или проверяемых серверов.

Имена выходов внутри каждого профиля — `proxy-0`, `proxy-1`, ...; селектор — префикс `proxy-`. Резервом служит первый пригодный узел этого профиля. В общем автовыборе у него стандартный вес 1, у остальных вес 2; в профилях стран все веса стандартные. Специфические веса чешского, шведского и британского серверов образца не копируются на посторонние серверы. Ссылок на отсутствующие выходы нет даже при пуле из одного узла.

Как в образце, сокеты используют IPv4 и TCP keepalive 30/15 секунд, TCP Fast Open для TCP, fingerprint Firefox. Для XHTTP сохраняется собственный режим источника (`stream-one`, `stream-up`, `packet-up` или `auto`); при отсутствии режима используется `auto`. Применяются параметры xmux образца при сохранении собственного host/path. Hysteria2 использует BBR, сохраняя свою авторизацию и обфускацию. Настройки `tcpNoDelay` из образца также передаются; их наличие в JSON не является подтверждением поддержки конкретным ядром. Включены счётчики входящего/исходящего трафика выходов.

VLESS Vision используется в обычном режиме `xtls-rprx-vision`, который намеренно перехватывает UDP/443, как в образце. Принудительная замена на `xtls-rprx-vision-udp443` отменена. Другой UDP и TCP сохраняются. Это не гарантия HTTP/3 на всех выходах: браузер должен иметь возможность перейти на HTTPS/TCP.

## Отбор и публикация

Источник — `bypass-all.txt` rjsxrd. Для этой планки качества допускаются VLESS с TLS/Reality и Hysteria2 с TLS; явный `allowInsecure` запрещён. Удаляются неподдерживаемые ядром конфигурации и известные входные/выходные IP из IPsum. Неизвестные выходы и все страны сохраняются. Все уникальные подключения, прошедшие текущие сетевые проверки, попадают в каталог; квоты «три на технологию» нет.

Дубли сравниваются после применения общих клиентских параметров: разные исходные fingerprints не создают два одинаковых опубликованных выхода. Метки дублей объединяются, чтобы не потерять сведения о стране или БС. Авторизация, SNI, порт и параметры транспорта остаются частью идентичности; общий IP не делает подключения дублями.

Каждому кандидату нужна серия из шести TLS-проверенных HTTPS HEAD через его публикуемые параметры: минимум пять успехов и медиана не больше 1500 мс. Контрольные HTTPS-сайты Google и Cloudflare чередуются; проверяется новое соединение, а не ICMP-пинг. Ошибка сертификата сразу отклоняет узел. Разброс считается относительно медианы каждого контрольного сайта отдельно. Ранжирование использует только текущую сборку; результаты прошлых запусков не загружаются и не влияют на отбор. Замер GitHub — стартовый ориентир, а не прогноз задержки из сети пользователя.

Для выходов без обычного Vision дополнительно требуется настоящее HTTP/3 через SOCKS5 UDP ASSOCIATE, без TCP-резерва: до двух проходов по доступным контрольным адресам. Для обычного Vision HTTP/3 явно пропускается как намеренно запрещённый режим; пропуск не записывается как успешная UDP-проверка. Успешный UDP не заменяет HTTPS-проверку. Тайм-аут одной сетевой операции — 4 секунды, до 24 кандидатов одновременно. Файлы для замера скорости не загружаются.

## Кандидаты для белых списков

Приоритет учитывает явные метки WL/White List/БС, метки CIDR и актуальные публичные справочники `whitelist-all.txt`/`cidrwhitelist.txt` самого rjsxrd. По убыванию: совпадение входного IP и SNI со справочниками; явная метка WL; метка CIDR; только IP; только SNI; отсутствие признаков. Эти признаки повышают позицию только после прохождения общей проверки качества. Недоступность справочников не удаляет рабочие серверы: остаются метки источника.

Совпадение SNI с разрешённым доменом или заявление автора не доказывает обход жёсткого БС. В отчёте сохраняются основания приоритета и `restricted_network_verified: false`. Проверки выполняются из GitHub, без доступа к ограниченной мобильной сети пользователя.

## Масштабирование и защита публикации

GitHub Actions запускает обновление каждые два часа, в минуту 17, по изменению исходников и вручную. Сборка разделена на три этапа:

1. **Prepare:** загрузить источник, нормализовать и удалить дубли, проверить поддержку ядром, зафиксировать настройки, справочники и контрольные суммы Xray/геобаз. Разбить кандидатов на задания — обычно по 500 узлов, максимум 32 задания.
2. **Probe:** динамическая матрица, максимум четыре задания параллельно. В каждом задании отдельно проверяется работоспособность контрольных сайтов, репутация и текущий HTTPS/HTTP3. Ядро и геобазы получаются из единого проверенного артефакта. Проверки ядра и сетевые тесты используют пакеты до 128 узлов; разрешение входного имени ограничено тремя секундами.
3. **Assemble:** принять результат каждого задания ровно один раз, проверить идентичность входов, покрытие всех кандидатов, ревизию, ядро и геобазы. Затем построить профили стран и общий автовыбор. Отсутствующий, повреждённый, чужой или отложенный результат не допускает частичной публикации.

Перед публикацией каждый полный профиль проверяется Xray. Сетевые фикстуры проверяют маршруты и блокировки, приоритет DNS и резерв, IPv4, стабильность и отказоустойчивость `leastLoad`, политику Vision и подлинность TLS в HTTP/3. Общие DNS/маршруты сверяются во всём каталоге, а их одинаковые сетевые сценарии выполняются один раз. Тесты покрывают один и 10 000 кандидатов, исчезновение групп, новые технологии, нормализацию дублей, приоритет БС и сбои матрицы. Синтетическая проверка масштаба не является проверкой 10 000 живых серверов.

При недоступной инфраструктуре, пустом результате, превышении бюджета или смене основной ветки во время проверки предыдущая публикация сохраняется. Два выходных файла публикуются одним git-коммитом. `report.json` содержит текущий каталог, основания приоритета, измерения и сведения о сборке; он не является входом следующего отбора. Кэшируется только публичный список репутации, а промежуточные артефакты одного запуска хранятся один день.

Защитные бюджеты: источник — 64 МБ, каждый полный конфиг — 800 000 байт UTF-16, вся подписка — 32 МБ UTF-8. Это наши ограничения публикации, не заявленные пределы INCY. Превышающий бюджет пул страны делится на части; если даже один узел или вся подписка не помещаются, сборщик сохраняет предыдущую публикацию. Неактивные профили не нагружают наблюдатель активного Xray, но большой каталог всё равно занимает память и место в интерфейсе клиента.

Репозиторий содержит подписку и отчёт, сборщик/парсер с лицензией, настройки, подготовку официального Xray и геоданных, публикацию и действующие проверки. Отдельных клиентских профилей или копий платных серверов нет.
