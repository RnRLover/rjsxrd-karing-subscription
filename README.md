# Общая подписка для Happ и INCY

**Добавьте один и тот же URL в оба клиента:**

https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/subscription.json

Подписка содержит один полный Xray-конфиг «Автовыбор». Выбирать сервер вручную не требуется: внутри находится проверенный пул и балансировщик. Команд установки профиля маршрутизации, Autorouting и зависимости от Cloudflare нет. Ранее добавленные экспериментальные профили и подписки следует удалить в клиентах отдельно: очистка GitHub не меняет настройки уже установленных приложений.

## Маршрутизация

| Трафик | Действие |
| --- | --- |
| Реклама из `geosite:category-ads-all` | Блокировать, в том числе на российских доменах |
| Российские сервисы `geosite:category-ru`, домены `.ru`, `.su`, `.рф` | Напрямую |
| Российские адреса `geoip:ru` | Напрямую |
| Частные сети `geoip:private` и имена `geosite:private` | Напрямую |
| Остальные TCP/UDP-соединения | Через автовыбор из пула |

Используются полные базы **Loyalsoldier**. `category-ads-all` объединяет, среди прочего, EasyList, AdGuard DNS Filter и дополнительные списки рекламных доменов. Это блокировка по доменам: реклама с того же домена, что и полезный контент, включая часть видеорекламы, может сохраняться. Блокировка всех рекламных вставок не обещается.

Sniffing HTTP/TLS/QUIC включён с `routeOnly: true`: восстановленное имя участвует в правилах, исходный адрес соединения сохраняется. `IPIfNonMatch` позволяет учитывать исходный RU-IP и затем проверять GeoIP для разрешённого имени. Безусловного финального правила, отменяющего второй проход, нет: оставшийся трафик попадает в пул через scoped loopback.

## DNS и усиление блокировки

В полном JSON задан собственный DNS, без FakeDNS. TCP/UDP-пакеты на порт 53, попавшие во входы Xray, направляются во встроенный DNS. Рекламные имена из той же `category-ads-all` получают `0.0.0.0`; этот адрес дополнительно блокируется маршрутизацией. Обычные соединения к рекламным доменам блокируются независимо от такого DNS-ответа.

Российские имена разрешаются через Yandex DNS `77.88.8.8` / `77.88.8.1` напрямую; остальные — через прямой DoH Cloudflare `1.1.1.1` с резервным Google DNS `8.8.8.8`. Прямой DNS не зависит от запуска балансировщика и проверки серверов. Для разрешения имён выбран `UseIPv4`, чтобы не зависеть от IPv6 у оператора и прокси; явные IPv6-соединения всё ещё классифицируются правилами IP. Локальные резолверы могут быть недоступны у отдельного оператора — это проверяется на устройстве.

DNS-перехват действует только на трафик, переданный ядру клиентским TUN/прокси. DNS-over-HTTPS внутри стороннего приложения не превращается в обычный DNS автоматически; скрытое ECH имя также может ограничивать доменную фильтрацию. Полный JSON применяется к этой конфигурации, отдельный глобальный профиль не устанавливается.

## Автовыбор и отбор пула

На устройстве работает `leastPing` с `burstObservatory`: интервал измерений 30 секунд, три последних измерения, тайм-аут 5 секунд. Средний цикл наблюдений составляет около 90 секунд; отказ и восстановление не обнаруживаются мгновенно. До получения результатов используется первый сервер из ранжированного пула. Проверки не разрывают уже установленные соединения.

GitHub сохраняет прежний механизм отбора: максимум 40 серверов, реальные HTTPS-проверки выхода за пределами RU, проверка TLS/REALITY, исключение выходов из IPsum, две независимые HTTPS-цели, загрузка полного блока 256 KiB с SHA256, история успешности и ограничения по повторению выходов, подсетей и хостов. Публикуется только проверенный пул; при неудачном обновлении сохраняется предыдущая подписка. Эти проверки выполняются из GitHub и не гарантируют доступность узла у конкретного оператора.

## Геобазы и границы автоматизации

JSON ссылается на категории из файлов `geoip.dat` и `geosite.dat`, доступных ядру приложения. Он содержит `geodata` с официальными HTTPS-адресами Loyalsoldier и обновлением в 00:17 и 12:17 по времени ядра, пока соединение работает.

**Раздел `geodata` не является установкой отсутствующих файлов с нуля.** Xray требует существующие файлы в своём каталоге ресурсов и права на запись для их замены. При отсутствии категории конфиг должен завершиться ошибкой, а не незаметно пропустить фильтрацию. Наличие и версия клиентских баз — условие работы GeoIP/GeoSite-правил. Проверка CI загружает именно Loyalsoldier; это не устанавливает базы на устройстве.

В предоставленных журналах Happ Android с Xray 26.10.21 активность обновления `geodata` не подтверждена. Установка подписки и актуальность клиентских баз должны проверяться на устройстве. Отдельные клиентские варианты не исправили бы эту неопределённость, поэтому оставлен один общий JSON. Для установки не требуется импортировать какой-либо профиль маршрутизации.

## Сборка и проверка

GitHub Actions запускается в минуты 7, 22, 37 и 52 каждого часа, а также вручную и при изменении исходников. Генерация получает обе базы Loyalsoldier, проверяет JSON официальным Xray, выполняет 21 сценарий маршрутизации/DNS и отдельный тест реального автовыбора с отказом выбранного узла. В локальных тестах меняются только транспортные фикстуры, адрес DNS-сервера и тайминги проверок; тестовые адреса не попадают в подписку. Проверки не заменяют проверку Android/iOS/Windows TUN в самом клиенте.

- `subscription.json` — единственный пользовательский файл подписки.
- `routing-policy.json`, `russia_config.py`, `karing.py` — настройки и сборка общего конфига; `routing-policy.json` не является импортируемым профилем клиента.
- `generate.py`, `rjsxrd_parser.py`, `routing.py`, `settings.json`, `certificate_checks.py`, `ip_reputation.py`, `latency_checks.py`, `pool_selection.py`, `quality_checks.py`, `quality-probe.bin` — действующий отбор и проверка серверов.
- `ru.json`, `report.json` — внутренний снимок пула и отчёт; не предназначены для импорта пользователем. `subscription_policy` содержит хеши баз и параметры итоговой политики.
- `setup_xray.py`, `publication_changed.py`, `check_subscription.py`, `check_auto_selection.py`, `test_*.py`, `.github/workflows/update.yml` — установка проверенного CI-ядра, тесты и публикация.
- `LICENSE.rjsxrd` — лицензия и атрибуция исходного парсера.

Смешанные форматы Happ/INCY, Worker, отдельные профили, наборы A/B и диагностические конфиги удалены. История Git сохраняет прежние реализации.

Документация: [Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat), [Xray DNS](https://xtls.github.io/en/config/dns.html), [Xray Routing](https://xtls.github.io/en/config/routing.html), [Xray Geodata](https://xtls.github.io/en/config/geodata.html).
