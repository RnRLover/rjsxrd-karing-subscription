# rjsxrd + правила Karing

Готовая подписка для INCY:

**https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/main/ru.json**

В INCY добавьте URL как подписку, обновите её и подключите единственный полный профиль. При первом подключении проверка выходов может занять около минуты. HTTP/SOCKS адреса в файле — локальные входы для клиента; на Android/TV системный VPN создаёт сам INCY, на Windows для игр требуется режим туннеля приложения, а не только системный HTTP-прокси.

## Что делает подписка

Источником серверов служит только проверенный whitelist-список [whoahaow/rjsxrd](https://github.com/whoahaow/rjsxrd): `githubmirror/bypass/bypass-all.txt`. Генератор переиспользует его MIT-конвертер конфигураций. Поддерживаются VLESS, Trojan, Shadowsocks AEAD и VMess через поддерживаемые TCP/WS/gRPC транспорты; небезопасные, неподдерживаемые и неразрешимые варианты исключаются. Это не полная копия всех 600+ исходных узлов.

Из [KaringX/karing-ruleset](https://github.com/KaringX/karing-ruleset/tree/sing) берётся выбранный набор правил в JSON. Это список правил для сценария в России, а не перенос всех настроек и выключенных категорий из Karing. Конкретные источники и порядок находятся в `settings.json`; контрольные суммы каждой загруженной версии — в `report.json`.

| Трафик | Действие | Правила Karing |
|---|---|---|
| Локальная сеть и имена роутеров | direct | LocalAreaNetwork |
| Рекламные домены | block | BanAD |
| OpenAI, Telegram, Discord | proxy | OpenAi, Telegram, Discord |
| Steam, Epic, EA/Origin, Sony, Nintendo | proxy | Соответствующие ACL4SSR rulesets |
| Российские сервисы и IP | direct | category-ru и geoip/ru |
| Остальной TCP и UDP | proxy | Общее завершающее правило |

Правила proxy для перечисленных сервисов стоят перед российскими direct-правилами. Доменные и IP условия разделяются при переводе в Xray, чтобы Telegram и другие наборы сохраняли альтернативы, а не требовали совпадения обоих условий одновременно. `geoip.dat`/`geosite.dat` не нужны: все выбранные условия встроены в файл.

## Как исключаются российские серверы

1. Исключаются ссылки с российским флагом или меткой RU/Russia/Россия.
2. IP адреса серверов проверяются по IPv4/IPv6 таблице RU из Karing; домены разрешаются, российские или неизвестные адреса исключаются.
3. Для кандидатов Xray создаёт временные локальные HTTP входы. Через каждый кандидат выполняется реальный HTTPS запрос к `api.ipify.org`; российские выходные IP по той же таблице и неработающие кандидаты исключаются.
4. До 24 прошедших проверку узлов входят в `ru.json`. Сохраняется исходный порядок качества rjsxrd; внутри устройства `burstObservatory` и `leastPing` выбирают доступный выход. Если весь пул недоступен, proxy трафик блокируется вместо прямого выхода.

Это проверка по обновляемой IP базе, а не гарантия физического местоположения сервера. Сервер с несколькими выходами может изменить IP после проверки. Проверки GitHub Actions не заменяют проверку доступности в вашей мобильной сети при БС.

## Обновление и сохранение исправной версии

GitHub Actions запускается каждый час, вручную и после изменения кода/настроек. Перед публикацией проходят тесты, проверка фактических выходов и `xray run -test` на официальном Xray `v26.3.27`. Контрольная сумма загруженного Xray сверяется с файлом издателя. При неудачной загрузке правил, пустом пуле или ошибке Xray новая версия не коммитится: прежняя рабочая подписка остаётся по тому же URL. Конкурирующие обновления выполняются последовательно, история публикаций сохраняется.

`report.json` содержит время последней успешной генерации и результат проверок. `servers.txt` — вспомогательный список отфильтрованных исходных ссылок; он не содержит встроенных правил и включает больше узлов, чем проверенный пул full-config. Для использования с правилами импортируйте **ru.json**.

## Локальный запуск

Требуется Python 3.12+. Сам генератор и конвертер используют только стандартную библиотеку. На Windows/Linux:

```sh
python -m unittest discover -v
python setup_xray.py
# Linux
python generate.py --xray .runtime/xray --verify-exits
# Windows
python generate.py --xray .runtime/xray.exe --verify-exits
```

`setup_xray.py` получает официальную сборку Windows x64 или Linux x64 для локальной проверки/Actions. Full JSON не содержит путей к этим файлам и предназначен также для Android/TV, macOS и других поддерживаемых INCY платформ. Автозагрузчик тестового бинарника для macOS/ARM сейчас не предусмотрен; существующий Xray можно передать через `--xray`.

## Что проверено и что нужно проверить на устройствах

Локальные тесты покрывают RU IPv4/IPv6 исключение, смешанные DNS ответы, преобразование правил, сохранение транспортов и запрет прямого fallback. Готовый JSON проверяется Xray и выбранные выходы — реальными HTTPS запросами. Время, количество узлов и версии исходных правил см. в `report.json`.

Поддержка full JSON с `inbounds`/`outbounds`, баланcерами и observatory описана [самим INCY](https://github.com/INCY-DEV/incy-docs/blob/main/ru/dev-docs/full-xray-config.en.md). Приложение исправляет локальные входы и получает конфигурацию почти без изменений. Android/TV и Windows заявлены в [официальной таблице платформ](https://github.com/INCY-DEV/incy-platforms). Импорт в реальные приложения в этой работе ещё не проверен.

На каждом устройстве нужно проверить: импорт и обновление URL, внешний IP, local/direct и ads/block, работу OpenAI/Telegram/Discord, голосовую связь и конкретную UDP игру. На ТВ можно использовать штатную отправку подписки с телефона. DNS оставлен под управлением INCY — его поведение и утечки проверяются на устройстве. HTTP проверки не доказывают качество UDP. При переключении выхода уже открытая игровая сессия может оборваться; отдельный профиль с постоянным сервером для игры можно добавить после первого теста.

Резерв через Яндекс и другие источники в эту упрощённую версию не включены. Возможные следующие улучшения: стабильный игровой выход, проверки UDP и fallback загрузки с последним локальным исправным JSON. Пока основной результат — одна обновляемая GitHub RAW ссылка.

## Происхождение и лицензии

`rjsxrd_parser.py` — `source/utils/vpn_config.py` из rjsxrd, commit `3c6df4dee94c434c19c6e1dfaed3c3f37fc5573d`, MIT. Сохранена `LICENSE.rjsxrd`; две зависимости приложения заменены автономными константами, адаптация транспортных параметров выполняется в `generate.py`. Правила Karing/ACL4SSR принадлежат соответствующим upstream проектам и загружаются с атрибуцией в отчёте. Свой клиент, VPN-сервер и сервер подписки не создаются.
