# rjsxrd: GeoSite/GeoIP, реклама и автоматический прокси

Готовая подписка для INCY:

**https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/ru.json**

Добавьте URL в INCY как подписку, обновите её и подключите единственный полный профиль. После первого подключения проверка серверов может занять около минуты.

## Встроенная маршрутизация

### Вариант Karing + наши RU правила

#### Одна ссылка для INCY — проверка совместимости

`https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/ru-karing-incy.txt`

Отдельный экспериментальный вариант содержит тот же полный Xray JSON, строку `://autorouting/onadd/` с URL `karing-routing.json` и интервал обновления подписки в один час. Actions обновляет его вместе с конфигом и геофайлами. Команда autorouting должна установить, активировать и затем обновлять профиль и базы без отдельного импорта.

В этой одной подписке JSON теперь является массивом полных конфигов: «Автовыбор», «VLESS», «Shadowsocks», «Trojan», «VMess». Отдельный протокол появляется только при наличии прошедших проверку серверов этого типа; пустые варианты не публикуются. «Автовыбор» использует весь проверенный пул, остальные балансируют только внутри выбранного протокола. Маршруты Karing, реклама, RU-direct в конце, TCP/UDP и блокировка при недоступности всего пула одинаковы. Каждый вариант проверяется Xray с нашими геофайлами; Android бюджет контролируется для каждого полного конфига отдельно. INCY документирует массив как несколько выбираемых серверов одной подписки; отображение имён и сочетание массива с командой авторутинга нужно подтвердить импортом в приложение.

Выбор кандидатов и итоговых 24 узлов чередует протоколы, сохраняя порядок качества источника внутри каждого типа. Поэтому серверы одного протокола в начале источника не вытесняют остальные до проверки. Неработающие и российские выходы по-прежнему не публикуются.

INCY документирует специальные строки в смешанных подписках, но пример относится к серверным URI, а сочетание с полным JSON явно не описано. Поэтому этот URL требует проверки в реальном INCY: импорт должен сохранить полный конфиг с балансировщиком, найти профиль из тела и загрузить обе базы. Проверки генератора подтверждают сохранность JSON и Xray маршрутов, а не поведение парсера INCY. Пока это не подтверждено, обычные `ru.json` и `ru-karing.json` остаются доступными по прежним URL. Если клиент не принимает такой формат, документированная альтернатива — тот же полный JSON с HTTP-заголовком `autorouting` на хостинге, который позволяет задавать заголовки; GitHub RAW не предоставляет нам такой настройки.

Документация: [форматы подписок](https://docs.incy.cc/subscription-format/), [autorouting](https://docs.incy.cc/autorouting/).

`ru-karing.json` переносит все 18 групп из [рекомендованного российского профиля Karing](https://github.com/KaringX/karing-ruleset/blob/sing/recommend/ru.json), сохраняя их порядок. Все группы включены, включая выключенные переключатели исходного шаблона. `currentSelected` заменён на наш балансировщик `auto`; `block` и `direct` сохранены. Поэтому Apple и OneDrive, как в исходном профиле, идут напрямую. Google/Gemini дополнены ранее использовавшимися Google API и списком `google-gemini`; первая группа рекламы дополнена нашим `category-ads-all`.

Порядок: локальная сеть → группы Karing в исходном порядке → наши RU домены напрямую → наши RU IP напрямую → всё остальное TCP/UDP через автоматический прокси. Общие RU правила не повторяются. Для каждой группы домены и IP преобразованы в отдельные последовательные Xray правила с одинаковым действием, чтобы сохранить условие «домен ИЛИ IP».

**Один раз перед переключением установите геофайлы:** добавьте в INCY автообновляемый профиль по ссылке `incy://autorouting/onadd/https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/karing-routing.json`. Дождитесь успешной загрузки обеих баз, затем добавьте подписку `https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/ru-karing.json` и подключите её. Если устройство не открывает deeplink, добавьте файл `karing-routing.json` через импорт профиля маршрутизации и настройте обновление источника в INCY. Для Android/TV и Windows требуется проверка этого импорта в установленном приложении; проверка Xray сама по себе не подтверждает импорт в INCY 3.7.0.

Профиль INCY здесь устанавливает и обновляет геофайлы; точный порядок маршрутов хранится в полном `ru-karing.json`. Простое импортирование профиля без переключения на этот full config не гарантирует порядок Karing.

Большие списки хранятся в `karing-geosite.dat` и `karing-geoip.dat`, а JSON содержит короткие ссылки на группы. Исходные категории официального Xray сохранены в обеих базах. Данные берутся из SRS Karing и декомпилируются официальным sing-box 1.14.2, проверенным по SHA256 выпуска; все новые файлы проверяются Xray с этими конкретными базами до публикации. Неизвестные условия, пустой источник или превышение бюджета размера останавливают публикацию.

**Обновление:** по часовому расписанию Actions обновляет серверы, исходный профиль Karing, все его списки и оба геофайла; публикует их одним коммитом после проверок. `ru-karing.json` обновляется при обновлении подписки в INCY. `karing-routing.json` имеет `LastUpdated` и меняющиеся URL баз при изменении их содержимого; INCY обновляет его по выбранному интервалу авторутинга (по умолчанию 24 часа). Можно выбрать 12 часов или обновлять вручную. Часовое расписание GitHub может выполняться с задержкой. Кэш GitHub RAW тоже может задержать получение новой версии. Имена групп неизменны, поэтому разные моменты обновления баз и JSON не меняют их назначение.

Действующий `ru.json` остаётся отдельным прежним вариантом: обновление подписки не должно автоматически переключать устройство на отсутствующие геофайлы. Для возврата используйте прежнюю подписку. Выбранный выходной IP и поддержка UDP по-прежнему требуют проверки на устройстве.

Сборка дополнительного варианта после обычной генерации:

```sh
python setup_singbox.py
python karing.py --xray .runtime/xray --singbox .runtime/sing-box
# Windows: .runtime/xray.exe и .runtime/sing-box.exe
```

Правила применяются в порядке:

1. GeoSite `category-ads-all` → block, включая рекламу на российских доменах.
2. Локальные/частные IPv4 и IPv6 → direct.
3. GeoSite `google-gemini` и общие Google API, вход и ресурсы приложения → автоматический пул прокси, даже при российском адресе Google CDN.
4. GeoSite `category-ru` → direct.
5. `geoip:ru` из установленной базы INCY → direct.
6. **Всё остальное, TCP и UDP, → автоматический пул прокси.**

Правило Gemini включает `google.com`, `googleapis.com`, `gstatic.com`, `googleusercontent.com`, `ggpht.com`, `.google` и обновляемый список `google-gemini`. Поэтому связанные сервисы Google (включая часть запросов Play и Google приложения) также используют прокси. Блокировка рекламы остаётся выше этого правила. Это устраняет возможный прямой выход к российским адресам API; работу Gemini на конкретном выходном IP подтверждает только проверка приложения. Географические ограничения или отказ Google для IP сервера могут сохраняться.

GeoSite использует готовые JSON экспорты [KaringX/karing-ruleset](https://github.com/KaringX/karing-ruleset). Генератор разворачивает их в стандартные Xray domain правила прямо в `ru.json`. Точные домены преобразуются в `full:`, суффиксы в `domain:`, регулярные выражения сохраняются; неизвестный тип правила останавливает публикацию. GeoIP маршрутизация использует стандартную ссылку `geoip:ru` и базу `geoip.dat`, уже установленную в INCY. При ошибке загрузки этой базы обновите геофайлы в INCY.

**Автообновление:** по часовому расписанию Actions получает свежие серверы, GeoSite списки и RU таблицу для исключения выходов, проверяет их и обновляет `ru.json`. INCY получает правила при своём обновлении подписки; после обновления переподключитесь. База GeoIP для маршрутизации теперь обновляется средствами INCY, отдельно от JSON подписки. Если любой источник или проверка недоступны, опубликованная версия сохраняется. URL и SHA256 источников записываются в `report.json`.

### Ограничение Android

В INCY 3.7.0 полный конфиг передаётся VPN сервису через Android Binder. Встраивание 25 тысяч RU подсетей привело к `TransactionTooLargeException` (в журнале пакет 1 161 624 байта). Теперь подсети заменены компактной ссылкой `geoip:ru`; GeoSite и рекламные правила сохранены. Перед публикацией проверяется консервативный бюджет 250 000 байт UTF-16 с запасом для изменений INCY. Это ограничение генератора, а не измерение итогового Android Parcel. Проверка Xray не заменяет проверку запуска на устройстве после перезагрузки.

`IPOnDemand` позволяет направлять домены с российским IP напрямую, даже если их нет в GeoSite. Это требует DNS-разрешения адресов; DNS остаётся под управлением INCY. При недоступном DNS IP-классификация может не сработать. GeoSite является классификацией списка, а не гарантией физического расположения сервиса; GeoIP зависит от актуальности данных. Блокировка рекламы действует на домены, не на отдельные рекламные элементы внутри разрешённого сайта.

Если AdGuard тоже включён, его правила действуют отдельно. Параметры локальной авторизации остаются под управлением INCY.

Источником серверов служит только проверенный whitelist список [whoahaow/rjsxrd](https://github.com/whoahaow/rjsxrd), `githubmirror/bypass/bypass-all.txt`. Игарек и зеркала не используются. Российские серверы исключаются по меткам, адресам серверов и фактическим HTTPS выходным IP. Домены серверов разрешаются; неизвестные, локальные и российские адреса исключаются. RU IP таблица Karing используется для исключения выходов на этапе генерации. Классификация назначений по `geoip:ru` выполняется базой INCY; версии данных могут различаться.

Генератор переиспользует MIT конвертер rjsxrd. В полный профиль входят до 24 работающих узлов, прошедших HTTPS проверку выхода. Поддерживаются VLESS, Trojan, Shadowsocks AEAD и VMess с поддерживаемыми TCP/WS/gRPC транспортами. Неподдерживаемые и небезопасные варианты пропускаются. `burstObservatory` и `leastPing` выбирают доступный сервер по задержке. Если весь пул недоступен, прокси трафик блокируется вместо прямого выхода.

GitHub Actions обновляет подписку каждый час, вручную и после изменения кода или настроек. Перед публикацией выполняются тесты, реальные HTTPS запросы через кандидатов и проверка JSON официальным Xray 26.3.27. Бинарник Xray сверяется с контрольной суммой издателя. При ошибке прежняя опубликованная подписка сохраняется. История публикаций остаётся в GitHub.

`report.json` содержит время генерации, число узлов и сведения о проверках. `servers.txt` является вспомогательным списком ссылок без встроенных правил; для автоматического выбора используйте **ru.json**.

## Локальный запуск

Python 3.12+, стандартная библиотека:

```sh
python -m unittest discover -v
python setup_xray.py
# Linux x64
python generate.py --xray .runtime/xray --verify-exits
# Windows x64
python generate.py --xray .runtime/xray.exe --verify-exits
```

Сам full JSON не содержит платформенных путей. Поддержка удалённых full конфигов описана [официально INCY](https://github.com/INCY-DEV/incy-docs/blob/main/ru/dev-docs/full-xray-config.en.md). На Android/TV и Windows импорт в реальное приложение ещё требует проверки. При использовании системного HTTP прокси UDP игр через него не передаётся; для такого трафика нужен поддерживаемый клиентом туннель или SOCKS UDP. DNS оставлен под управлением INCY.

Готовый full конфиг проверен Xray, а HTTPS запрос через его балансировщик выполнен успешно. Локальная UDP/STUN проверка не получила ответа; совместимость с играми не подтверждена. Внешний IP может измениться при переключении сервера и оборвать игровую сессию. Возможное следующее улучшение — отдельный стабильный игровой выход с проверкой UDP. Дополнительных игровых режимов в этой версии нет.

`rjsxrd_parser.py` взят из `source/utils/vpn_config.py` rjsxrd, commit `3c6df4dee94c434c19c6e1dfaed3c3f37fc5573d`, MIT; лицензия сохранена в `LICENSE.rjsxrd`. Две зависимости исходного приложения заменены автономными константами. Название репозитория сохранено для неизменности URL.
