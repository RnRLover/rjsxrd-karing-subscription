# Подписка rjsxrd для INCY

Добавьте в актуальный INCY один URL:

https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/subscription.json

Подписка содержит один полный Xray-конфиг «Автовыбор» и команду автоматического импорта `incy-routing.json`. Профиль подключается к подписке средствами INCY, загружает геобазы Loyalsoldier и автоматически обновляется по своему URL. Интервал проверки геобаз — 24 часа; явный выбор пользователя в клиенте имеет приоритет. Отдельный ручной импорт профиля не нужен.

Имя `subscription.json` сохранено ради существующих URL. Содержимое теперь использует смешанный формат INCY: JSON-массив на первой строке, далее команда autorouting и метаданные. Это не самостоятельный JSON-документ для других клиентов. Поддержка Happ прекращена.

## Правила

| Назначение | Маршрут |
| --- | --- |
| `geosite:category-ads-all` | Блокировать, включая рекламу на российских доменах |
| RU-сервисы, `.ru`, `.su`, `.рф`, `geoip:ru` | Напрямую |
| LAN и `geosite:private` | Напрямую |
| `geosite:github` | Напрямую |
| Остальной TCP/UDP-трафик | Автовыбор из общего пула |

Категория GitHub включает API, raw-файлы, загрузки релизов, Pages и другие связанные домены, включая npm и GitHub Copilot. Точные категории берутся из полных баз Loyalsoldier. Правила профиля и полного конфига формируются из одного `incy-routing.json`.

Блокировка действует по доменам. Она не удаляет рекламные вставки, неотличимые по домену от полезного контента. Собственный DoH стороннего приложения также не становится обычным DNS автоматически.

## DNS, Internal (mapped), IPv6

Режим Internal (mapped) в клиенте сохраняется. Его виртуальные адреса нужны для восстановления исходного домена внутри VPN; `FakeDNS: false` в профиле не выключает HEV mapdns. Особенности этого режима на разных платформах реализуются самим INCY.

Все публичные имена — зарубежные сайты, RU/GitHub и доменные адреса VPN-серверов — разрешаются через прямой DoH. Основной резолвер Cloudflare, резервный Google. Оба используют HTTPS с проверкой сертификата и не зависят от автопула. Обычный UDP-DNS `77.88.8.8` удалён из полного конфига и привязанного профиля; открытого DNS-резерва для публичных доменов нет. Частные имена используют системный резолвер.

Основной URL — `https://cloudflare-dns.com/dns-query`, резервный — `https://dns.google/dns-query`. Их bootstrap-IP закреплены в `dns.hosts`, а тег `dns-remote` направляется в `direct`. Поэтому для обращения к DoH не требуется сначала получить DNS-ответ через VPN. Нативный профиль задаёт DoH для обеих DNS-категорий; дополнительный резолвер задан в полном JSON. Интернет-провайдер видит соединение с DoH-сервисом, содержимое DNS-запросов зашифровано. Маршрутизация самих сайтов остаётся прежней. Проверка на реальном устройстве и конкретной сборке INCY остаётся отдельной от стенда Go Xray.

Перехват DNS действует на TCP/UDP-порт 53 у входов полного конфига. A и AAAA обрабатываются встроенным DNS. Прочие типы получают быстрый пустой NOERROR вместо молчаливого отбрасывания; полного DNS-сервера для TXT/SRV этот конфиг не предоставляет.

Включены A/AAAA и поддержка IPv4/IPv6. Прямые TCP-соединения и TCP-адреса прокси используют встроенный DNS и Happy Eyeballs: IPv4 в приоритете, IPv6 пробуется при необходимости. Для QUIC-подключения Hysteria2 адрес сервера разрешается сначала в IPv4, затем в IPv6 при отсутствии A-записи; TCP Happy Eyeballs к UDP-сокету не применяется. Возможность удалённого сервера выйти к IPv6-назначению зависит от самого сервера.

Профиль не изменяет системный IPv6-переключатель/TUN. Если IPv6 ранее отключили в настройках INCY, для его использования потребуется вернуть авто/двойной режим клиента. Сам JSON больше не ограничен IPv4.

## Пул и автовыбор

Источник — проверенный `bypass-all.txt` rjsxrd. После удаления точных дублей, несовместимых конфигураций и известных спам-адресов берутся первые **три записи каждой технологии** в исходном порядке rjsxrd. Технология определяется сочетанием протокола, транспорта и защиты: например, VLESS/TCP/Reality, VLESS/XHTTP/Reality и VLESS/XHTTP/TLS — разные группы. Если пригодных записей в группе меньше трёх, сохраняются все имеющиеся. Лимит задаётся `max_nodes_per_technology` в `settings.json`.

Собственного ранжирования по пингу GitHub, фильтра страны, дополнительных ограничений по хосту/подсети/выходу, истории измерений и проверок качества TCP/UDP нет. Загрузка тестовых файлов отсутствует.

Удаляются точные дубликаты, конфигурации, которые ядро физически не может загрузить, и узлы с известным адресом в IPsum. Репутация проверяется для разрешённых входных IP и обнаруженного выходного IP. Один небольшой HTTPS-запрос через туннель служит только для определения выхода; его время и успех не используются для сортировки или допуска. При неудаче узел сохраняется с неизвестной репутацией. Отсутствие IP в IPsum не является доказательством безопасности; покрытие отсутствующих IPv6-адресов помечается как неизвестное.

Отобранные записи сохраняют общий исходный порядок и передаются одному `leastPing`. Группировка применяется только для ограничения числа кандидатов; отдельных балансировщиков технологий и приоритетов между ними нет. До первых результатов используется первый узел оставшегося списка. Первая проверка запускается сразу параллельно со стартом; следующие — в среднем раз в минуту на узел, одно измерение, тайм-аут 4 секунды. Проверки — HTTPS HEAD без тестового файла. Они не переносят и не разрывают уже установленные соединения. Отказ сервера обнаруживается с задержкой, зависящей от расписания наблюдений.

Поддерживаются VLESS, VMess, Trojan, Shadowsocks и Hysteria2, включая поддерживаемые Xray транспорты TCP/RAW, WebSocket, gRPC, HTTPUpgrade и XHTTP. Параметры разбираются обновлённым парсером rjsxrd; они не заменяются одной предпочтительной технологией.

Для VLESS Vision в публикуемом конфиге используется `xtls-rprx-vision-udp443`: Vision сохраняется, а встроенный запрет клиента Xray на UDP/443 снимается. Это позволяет передавать браузерный QUIC через такие узлы; реальная доступность UDP по-прежнему зависит от сервера и сети. Проверка HTTPS HEAD не подтверждает работоспособность UDP. Локальная проверка CI воспроизводит отказ обычного Vision и проверяет передачу UDP/443, UDP на другом порту и TCP с опубликованными настройками Vision через настоящий Xray.

После отбора по три записи на технологию дополнительных сокращений пула нет. Для полного конфига действует защитный предел 800 000 байт UTF-16; это запас перед передачей клиенту, а не измеренный предел Android IPC. В тестах проверяются квоты, исходный порядок, исключение спам-адресов до применения квоты и сохранение всех переданных сборщику узлов.

## Обновление и проверка

GitHub Actions обновляет подписку в минуты 7, 22, 37 и 52 каждого часа, по изменению исходников и вручную. Каждый запуск получает текущий набор; кешируется только IPsum, а не измерения серверов. При неудачной сборке сохраняется предыдущая публикация. Перед push проверяется, что ветка не изменилась; устаревшая сборка не перезаписывает более свежий код.

Проверяются формат доставки и профиль, загрузка полного JSON официальным Xray, реальные маршруты на локальных транспортных фикстурах, DNS с учётом патча INCY, A/AAAA, работа внешнего DoH при недоступном пуле, переключение на резервный DoH, отсутствие открытого DNS-резерва для внешних доменов, резервный DoH для GitHub и адресов прокси, отсутствие открытого DNS-резерва при отказе обоих DoH, выбор/отказ узла и настоящие IPv4/IPv6 TCP-соединения.

`report.json` содержит отчёт только текущей опубликованной сборки. Он не является входом отбора и не используется для ранжирования. Установка профиля/геобаз в самом приложении не выдаётся за проверенную на устройстве: соответствующий флаг отчёта остаётся `false`.

## Файлы

- `subscription.json` — единственный URL пользовательской подписки.
- `incy-routing.json` — привязанный профиль, источник правил и DNS, адреса геобаз.
- `settings.json` — источник серверов, параметры определения репутации и наблюдений.
- `generate.py`, `incy.py`, `ip_reputation.py` — сборка, доставка, маршрутизация и фильтр известных адресов.
- `rjsxrd_parser.py`, `rjsxrd_helpers.py`, `LICENSE.rjsxrd` — необходимые части MIT-парсера rjsxrd и лицензия.
- `setup_xray.py`, `publish_subscription.py`, `.github/workflows/update.yml` — подготовка ядра и безопасная публикация.
- `check_*.py`, `test_*.py` — действующие проверки.
- `report.json` — диагностика текущей сборки.

Документация: [INCY](https://docs.incy.cc/), [Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat), [Xray](https://xtls.github.io/en/config/).
