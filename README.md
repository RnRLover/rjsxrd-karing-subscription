# Подписка rjsxrd для INCY

Добавьте в актуальный INCY один URL:

https://raw.githubusercontent.com/RnRLover/rjsxrd-karing-subscription/refs/heads/main/subscription.json

Подписка содержит компактный общий автовыбор и полный каталог профилей «страна + технология». Страны и технологии определяются из свежего пула rjsxrd при каждой сборке. Новые группы появляются автоматически, исчезнувшие удаляются из следующей публикации. Список стран или технологий вручную не задаётся.

Каждый полный Xray-конфиг повторяет клиентскую логику предоставленного образца: IPv4, `leastLoad`, геоблокировка рекламы и телеметрии Windows, его прямые маршруты и исключения. DNS полностью совпадает с образцом: Яндекс DoH, Cloudflare DoH и обычный Cloudflare DNS в резерве. Серверы, авторизация, порты, ключи, SNI, пути и обязательные параметры транспортов берутся из rjsxrd. Данные доступа из образца в репозитории отсутствуют.

Доставка — один JSON-массив на первой строке и метаданные названия подписки. Отдельного профиля маршрутизации и команд Routing/Autorouting нет. Прежний отдельный профиль следует оставить выключенным. Геобазы нужны Xray и используются из файлов INCY; CI проверяет конфиг со свежими файлами Loyalsoldier, но не подтверждает состояние геофайлов на телефоне.

## DNS

Порядок серверов сохранён относительно образца:

| Позиция | Сервер | Назначение |
|---|---|---|
| 1 | `https://77.88.8.8/dns-query` | Яндекс DoH, категории `category-ru` и `category-gov-ru` имеют приоритет |
| 2 | `https://1.1.1.1/dns-query` | Cloudflare DoH |
| 3 | `1.0.0.1` | Обычный Cloudflare DNS по UDP/53 |

Как в образце, у Яндекса не включён `skipFallback`: он может обслуживать также нероссийские имена. При отказе обоих DoH разрешён обычный UDP-резерв Cloudflare. Проверка сертификатов HTTPS сохранена. Блокировка рекламы выполняется геосписками маршрутизации, а не фильтрующим DNS.

В DNS нет добавленных нами `tag`, `hosts`, закреплённых адресов AdGuard и отдельного прямого правила. DNS-запросы подчиняются тем же правилам маршрутизации, что в образце: IP Яндекса совпадает с `geoip:ru` и идёт напрямую, IP Cloudflare обычно попадают в балансировщик. Поэтому работа резервного DNS может зависеть от пула; отдельного прямого bootstrap подписка не задаёт. INCY может дополнить правила своими DNS-IP-исключениями.

Режим VPN DNS задаёт INCY. Как в образце, JSON не содержит собственного перехвата клиентского TCP/UDP-порта 53 или отдельного DNS-outbound. Режим Internal (mapped) и работу системного TUN обеспечивает клиент. `UseIPv4` используется во встроенном DNS, прямом выходе и сокетах прокси; системный переключатель IPv6 подписка не изменяет. Наличие буквального IPv6-адреса не означает, что JSON блокирует IPv6 на уровне системы.

## Маршрутизация

Правила проверяются в следующем порядке:

| Назначение | Маршрут |
|---|---|
| `geosite:win-spy`, `geosite:category-ads` | Блокировать |
| BitTorrent | Напрямую |
| Habr, 4PDA, перечисленные в образце `.ru`/`.su`-исключения | Через пул |
| `private`, `apple`, `twitch`, `category-gov-ru`, `category-ru` | Напрямую |
| `geoip:ru`, `geoip:private` | Напрямую |
| Остальной TCP/UDP | Общий балансировщик |

Список прокси-исключений: `habr.com`, `4pda.to`, `kemono.su`, `jut.su`, `kara.su`, `theins.ru`, `tvrain.ru`, `echo.msk.ru`, `the-village.ru`, `snob.ru`, `novayagazeta.ru`, `moscowtimes.ru`. Синтаксис доменов сохранён из образца.

Используется `AsIs`: домены специально не разрешаются ради GeoIP. Прежние дополнительные правила `.ru`/`.su`/`.рф`, прямой категории GitHub и блокировки нулевых DNS-адресов удалены. GitHub теперь следует обычным правилам образца и обычно идёт через пул. SOCKS/HTTP-входы и отсутствие явного `listen` сохранены из образца, порты 10808/10809; sniffing включает HTTP и TLS без QUIC и без `routeOnly`.

## Автовыбор и транспорты

| Профиль | Состав | Автовыбор |
|---|---|---|
| `⚡ Автовыбор` | Первые представители актуальных групп, до 64 узлов | `expected: 1`, веса 1/2 |
| Страна + протокол/транспорт/защита | Все пригодные узлы этой группы, до 50 в одном профиле | `expected: 4`, `baselines: [400ms, 800ms]`, равные веса |

Крупная группа разбивается на части, сохраняя все узлы и их порядок в источнике. Общий автовыбор получает по одному первому представителю группы с чередованием технологий до заполнения лимита: многочисленная технология не занимает весь бюджет раньше остальных. Лимит общего автовыбора не удаляет остальные серверы из каталога. Общий автовыбор не переключается автоматически на другой полный профиль.

Страна берётся из явного `OUT`/`EXIT`, единственного флага или повторённого кода страны в структурированной метке rjsxrd. Несколько разных флагов без явной метки выхода и отсутствие метки означают «Страна не указана»; такие узлы сохраняются. Флаги ЕС/ООН не считаются странами. Это группировка по метаданным источника, а не независимое подтверждение географии выхода; геолокация входного IP не подменяет выход.

Каждый профиль имеет собственные `outbounds`, балансировщик и наблюдатель. Неактивные полные профили не входят в список проверок активного Xray. Наблюдатель проверяет `https://www.gstatic.com/generate_204`; средний интервал 5 минут, два последних результата, тайм-аут 5 секунд, метод HEAD по умолчанию Xray. Это статистика недавних наблюдений в памяти клиента, а не сохранённая история GitHub. Выбор учитывает разброс задержки, отказы и веса, не измеряет пропускную способность или загрузку CPU сервера. Реакция на отказ зависит от расписания проверок. `expected: 4` с baselines не является жёстким лимитом числа выбранных или проверяемых серверов.

Имена выходов внутри каждого профиля — `proxy-0`, `proxy-1`, ...; селектор — префикс `proxy-`. Резервом служит первый пригодный узел этого профиля. В общем автовыборе у него стандартный вес 1, у остальных вес 2; в профилях стран все веса стандартные. Специфические веса чешского, шведского и британского серверов образца не копируются на посторонние серверы. Ссылок на отсутствующие выходы нет даже при пуле из одного узла.

Как в образце, сокеты используют IPv4 и TCP keepalive 30/15 секунд, TCP Fast Open для TCP, fingerprint Firefox. Для XHTTP применены `stream-up` и параметры xmux образца при сохранении собственного host/path; Hysteria2 использует BBR, сохраняя свою авторизацию и обфускацию. Настройки `tcpNoDelay` из образца также передаются; их наличие в JSON не является подтверждением поддержки конкретным ядром. Включены счётчики входящего/исходящего трафика выходов.

VLESS Vision используется в обычном режиме `xtls-rprx-vision`, который намеренно перехватывает UDP/443, как в образце. Принудительная замена на `xtls-rprx-vision-udp443` отменена. Другой UDP и TCP сохраняются. Это не гарантия HTTP/3 на всех выходах: браузер должен иметь возможность перейти на HTTPS/TCP.

## Отбор и публикация

Источник — `bypass-all.txt` rjsxrd. Удаляются точные дубли, неподдерживаемые ядром конфигурации и известные входные/выходные IP из IPsum. Неизвестные выходы и все страны сохраняются. Все записи, прошедшие текущие сетевые проверки, попадают в каталог; прежняя квота «три на технологию» удалена. Ранжирования по истории или пингу GitHub нет.

Каждому кандидату нужен успешный TLS-проверенный HTTPS HEAD через его публикуемые параметры. Для выходов без обычного Vision дополнительно требуется настоящее HTTP/3 через SOCKS5 UDP ASSOCIATE, без TCP-резерва. Для обычного Vision HTTP/3 явно пропускается как намеренно запрещённый режим: пропуск не записывается как успешная UDP-проверка. Это не исключает рабочие Vision-узлы из-за ограничения самого клиентского конфига.

Проверки GitHub используют независимые контрольные сайты Google и Cloudflare; они не являются DNS-провайдерами подписки. До двух попыток, тайм-аут 4 секунды, 24 параллельных кандидата. При росте пула проверки обрабатываются порциями по 128 узлов, чтобы не создавать один огромный тестовый конфиг и не открывать все порты сразу. Файлы для замера скорости не загружаются. При недоступной инфраструктуре проверок или отсутствии пригодных кандидатов предыдущая публикация сохраняется.

GitHub Actions обновляет подписку в минуты 7, 22, 37 и 52 каждого часа, по изменению исходников и вручную. Перед публикацией каждый профиль проверяется ядром Xray, а совпадение DNS/маршрутов проверяется для всего каталога. Общий шаблон маршрутов испытывается один раз, чтобы рост числа стран не умножал одинаковые сетевые фикстуры. Также проверяются приоритет DNS и резерв, IPv4, стабильность/отказоустойчивость `leastLoad`, политика Vision и подлинность TLS в HTTP/3. Тесты моделируют рост с 10 до 50 стран, исчезновение групп, новые технологии и разделение больших групп без потерь. Локальные фикстуры не являются проверкой связи на телефоне.

`report.json` содержит текущий каталог, распределение узлов по профилям и отчёт проверок; он не используется как история отбора. Защитный бюджет каждого полного конфига — 800 000 байт UTF-16; бюджет всей подписки — 8 МБ UTF-8. Это наши ограничения публикации, не заявленные пределы INCY. При превышении бюджета сборка отказывается публиковать частичный каталог.

Репозиторий содержит подписку и отчёт, сборщик/парсер с лицензией, настройки, подготовку официального Xray и геоданных, публикацию и действующие проверки. Отдельных клиентских профилей или копий платных серверов нет.
